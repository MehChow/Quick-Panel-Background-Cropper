# Project documentation

Use these maintained references for current behavior. Release metadata lives in
`app.json`; framework and package versions live in `package.json`.

- [Product behavior](product-behavior.md): supported paths and user-visible contracts.
- [Architecture](architecture.md): geometry, rendering, gestures, persistence and compatibility.
- [Styling](styling.md): the existing UI baseline, to be superseded during the UI revamp.
- [Testing](testing.md): automated checks and test boundaries.
- [Manual acceptance](production-manual-test-checklist.md): current device regression checklist.
- [Cache ownership](cache-optimization.md): cleanup lifetimes and measurement.
- [Build setup](how-to-build.md), [Play upload setup](play-upload-setup.md),
  and [release workflow](dev-release-flow.md): local build and publishing operations.
- [Release announcements](release-announcement-guideline.md): localized startup notices.
- [Privacy policy](index.html): public policy page; retain its URL and deployment role.
- [Deferred My Icons proposal](backlog/my-icons-library.md): future work, not current behavior.

Completed implementation plans, historical release checklists, and superseded
handoffs are available in Git history. They are not current requirements.
Keep durable decisions in the relevant document above instead of accumulating
contradictory chronological notes. Retire completed plans after transferring
their remaining constraints or open work into maintained references.
